# Architecture

This project is a Python-based AI voice caller built to test a healthcare voice agent. The system uses Twilio to place outbound calls to the Pretty Good AI test number. When a call starts, Twilio connects the call audio to a local FastAPI server through a WebSocket media stream. The FastAPI server is exposed publicly using ngrok, so Twilio can reach the `/twiml` and `/media-stream/{scenario_id}` endpoints.

The FastAPI server acts as a real-time bridge between Twilio and the OpenAI Realtime API. Incoming caller audio from Twilio is streamed to OpenAI, and OpenAI generates the simulated patient’s spoken response based on the selected scenario prompt. The response audio is streamed back to Twilio so the clinic agent can hear it during the live call. Each scenario defines a fake patient name, goal, date of birth, phone number, opening line, and behavior rules. This lets the bot simulate different patient workflows such as scheduling, rescheduling, canceling, medication refill requests, insurance questions, billing questions, and edge cases.

The project records calls through Twilio and then transcribes the audio using an OpenAI transcription model. Each call artifact is stored under the `calls/` directory with a recording, transcript, and notes file. The transcripts are reviewed manually to identify agent quality issues, missed workflows, repeated verification loops, wrong identity handling, and other bugs. The code is organized into separate modules for call handling, scenario prompts, and transcription so the system can be run repeatedly with different `SCENARIO_ID` values.
